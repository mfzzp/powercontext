# 复现与验收样例

以下是待开发的功能验收要求，不是已通过的测试记录。具体入口、命令由 Qoder 实现后补充到 RUN.md。

## 样例 A：薄弱点与跨启动接力

1. 启动全新数据目录，使用新存档码 `learner-a-001`；选择 Python 主题。
2. 进入一题 P1，查看参考答案，自评“不会”（0），记录返回的真实 citation。
3. 换另一题 P2，自评“掌握”（2）。继续复习页应显示 P1 为薄弱题，掌握数量为 1；下一题优先 P1。
4. 关闭后端进程，使用原数据目录重新启动，再输入相同存档码。
5. 预期：P1、P2 及自评保持；下一题和推荐原因保持；可以根据保存的 citation 精确回读原始练习记录。
6. 对 P1 再次自评“掌握”（2）。掌握数量变成 2，P1 不再按旧的“不会”状态推荐；原来的练习引用仍可读。

## 样例 B：隔离与幂等

1. 新用户 `learner-b-001` 的历史为空，不能显示 A 的进度。
2. 对 A 重放同一练习请求 ID 和完全相同的数据，不新增练习记录，不增加掌握数量。
3. 相同请求 ID 变更自评或题目，必须报冲突，原记录保持。
4. 分数输入 true、"1"、1.0、-1、3 应失败，且不写入记忆；无效主题或题目也应失败。

## 样例 C：端到端与错误反馈

1. 浏览器中完成一次输入存档码、选题、看答案、自评、保存、继续复习。
2. 实际模拟记忆写入失败，界面提示保存失败，不宣称成功；恢复后重试可保存。
3. 核对原生 PowerContext 读写日志与页面返回的精确引用，记录实际命令、退出码、代码版本和界面截图。

## 样例 D：公开项目入口

1. 通过 Qoder Sites 发布项目网站，可见范围为“任何人都可访问”。
2. 无痕窗口打开 URL，不登录也能查看项目说明、截图/视频、仓库链接和运行体验方式。
3. 记录实际 Qoder UID、站点 URL、开发截图和验证时间；未部署线上应用时明确标注“下载后按说明本地体验”。
