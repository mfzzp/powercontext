# SDD 上下文模块技术说明

本模块以工单状态筛选为一项可验证的局部开发任务。它把有效规格、实现和测试组合为模型的输入，并用真实资料版本与验证结果保持任务连续性。

## 数据与执行路径

CLI `ingest` 读取清单中的真实文件，校验路径和大小，将项目编号、路径、种类、正文、SHA256、版本存入 seekdb 的 `sdd_documents`。修改后的规格覆盖同一路径并增加版本；未变化内容不增加版本。更新在数据库事务内完成，失败回滚，项目编号隔离不同验证运行。

CLI `context` 将任务查询词拆分为普通词，通过参数化 SQL 按正文匹配词数排序。模型上下文使用这次 SQL 实际返回的内容，并附上文件路径、行号、摘要及版本。示例查询包含规格、业务函数、目标测试、回归测试，排除无关账单规格。整个模块没有按任务 ID 硬编码资料答案。

PowerContext 的 SQLiteProfile 管理本地数据库连接和 schema；ArtifactRepository 保存 `sdd-progress` 家族的不可变修订。内容包含已完成步骤、待办步骤、测试退出码和来源摘要。状态不是只写日志：demo 启动新的 Python 进程读取它，把恢复的资料和进度一起传给 MiniMax；完成后再启动新进程并据此选择 `complete`。资料发生变化时改为 `revalidate_changed_sources`。

MiniMax 经 HTTP Chat Completions 接口收到当前任务、数据库来源、恢复状态和修改范围。真实示例使用 MiniMax-M3，仅允许生成 `ticket_app.py` 的完整源代码。响应经结构及语法检查后应用，运行固定的目标测试与回归测试。测试哈希须与修改前一致，否则流程失败。

## 验证与复现

修改前：目标 7 项失败且均为功能断言，回归 6 项通过。修改后：同一组 13 项全部通过。真实模型响应、请求上下文、补丁、测试命令/退出码/代码摘要、SQL 检索记录和 PowerContext 写入及重启读取记录位于 `evidence/live/`。

评审可用交付的真实响应运行 `demo --replay`，从新工程、新数据库项目编号、新 PowerContext 文件开始复现，不依赖作者机器的数据或 Key。回放明确标记未再次请求模型。也可配置自己的 MiniMax Key 运行实时 demo。规格更新、项目隔离、删除资料、路径边界及跨进程状态复用由模块集成测试覆盖。

工程资料采用小规模词法检索，未添加嵌入服务；任务状态采用 PowerContext SDK 的本地持久化能力，无需单独的 PowerContext HTTP 服务。这样三项指定技术各自参与必要环节，运行依赖和证据链都较小。Linux/Docker 仍需在评审或服务器环境复核，本地结果来自 Windows seekdb 1.4.0.0。
